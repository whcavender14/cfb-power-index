# Player features: Stage 0 audit (2026-09-30)

This audit is the baseline for Stages 1–4 (`PLAYER_FEATURES_SPEC.md`, `PLAYER_FEATURES_DECISIONS.md`). It changed no code.
Live CFBD probes ran on 2026-09-30 against API 5.31.2. They used 14 calls, and the account had 1,910 calls left afterwards.
The site data was at ratings week 4, exported 2026-09-29.

|---|---|---|

| `v2/players.json` | same script | 5,554 rows, 233 KB / 81.6 KB gz. No budget line, no validator |

| Team leaders | `pull_player_stats.R` (CI, 1 call) → `team/<slug>.json` | 10 per team (1+2+3+3+1), not 12 |

| `talent_2014_2026.rds` | frozen **model input**, SportsDataverse | 3,972 team-seasons, 2014–2026; full team names ("Alabama Crimson Tide") |

The profile exporter re-pulls on every run: game info, all current-season weeks, recruiting classes 2018–2026 (9 calls) and the portal for 2022–2026 (5 calls). Only past-season game logs are cached.

The profiles find portal history only by name and origin school, and only among players who appear in box scores.

The weekly refresh rewrites `usage/*.json`. Since 2026-09-26 the depth-chart starters have lost their `athlete_id` and stat lines (0 of 3,100 starters keep them). This bug existed before this work and is flagged as a separate task.

The validator does not check `player/`, `players.json`, `usage/`, `efficiency.json` or `game_adv/`. There is no sitemap; prerender routes are a hand-kept list in `scripts/prerender_routes.mjs`.

Discrepancies:
- **cfbfastR 3.0.0.9000 (GitHub dev, local) has `cfbd_metrics_ppa_players_season/_games` and `cfbd_stats_player_success`.** "No PPA wrapper" is wrong for this version.
- CI installs `any::cfbfastR` (CRAN), which may be a different version from local. That is a column-name drift risk.
- The spec lists player PPA as an input for DL/LB/DB, but CFBD has none for defenders.
- Locally, R runs in a French non-UTF-8 locale, and `writeLines` mangled "San José State" to `<U+00E9>`. Local pulls need `LC_ALL=en_US.UTF-8`. CI already sets C.UTF-8.
